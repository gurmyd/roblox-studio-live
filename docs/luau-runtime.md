# Luau runtime — module layout and how to add an op

The Studio side is two layers: the **bootstrap** (`plugin/bootstrap.luau`, the only file installed into Studio) and the **runtime bundle** (`plugin/runtime/**/*.luau`, shipped inside the npm package and pushed by the bridge on every connect). The wire contract is [protocol.md](protocol.md); verified engine behaviour is in [live-measurements.md](live-measurements.md).

## Bootstrap (`plugin/bootstrap.luau`)

Dependency-free, ~610 lines. It only knows: role detection (`edit` / `server` / `client`), the L1 WebSocket hello (edit DM) or the L2 PluginConnection hello (play DMs), §3 chunk split/reassembly (on UTF-8 character boundaries), bundle → in-memory tree, reconnect (0.5 → 5 s jittered backoff, proactive refresh at 25 min; the hub keeps requests alive across it), and `plugin.Unloading` cleanup. The bridge port is a literal on its own line (`local DEFAULT_PORT = 47800`) that `studio-live install` rewrites from `STUDIO_LIVE_PORT`. **It cannot be hot-updated** — everything that may change lives in the bundle.

The bundle becomes an **unparented** `Folder` named `StudioLiveRuntime`: path `runtime/hub/link` → `Folder runtime` → `Folder hub` → `ModuleScript link`; a segment named `init` is a plain `ModuleScript` named `init` (no Rojo folding). The bootstrap `require`s the entry and calls `start(ctx)`; the returned table must provide `stop()` and `relinked(ackUpto?)`, and may provide `lastSeq()`.

The `Link` object given to the runtime (`ctx.link`) is `send(text) -> bool`, `onFrame(fn(text, decoded?)) -> disconnect`, `isOpen()`, `stats()`. Frames reaching the runtime are always whole (chunks are reassembled in the bootstrap; outbound frames over 512 KB on L1 / 16 KB on L2 are split by `send`). `decoded` is the already-parsed frame table — an optimisation, the text is authoritative. Frames that arrive while a new bundle is starting are queued by the bootstrap and delivered to the **new** runtime once `start()` returns — the persisted-controller re-install relies on this.

Two bootstrap facts the runtime builds on: the session GUID is generated once per plugin load and survives runtime restarts (bundle updates), and `ctx.lastSeq` carries the seq / aseq the previous runtime reached, so a replacement runtime resumes numbering (the agent also uses it to tell a restart from a fresh start). `ctx.plugin` is the real `Plugin` object, but **plugin settings are unusable**: measured live on Studio 0.738, `plugin:GetSetting` returns `nil` for every key, even right after `SetSetting` — nothing in the runtime may depend on them (durable state lives in the bridge).

Every module `require`s siblings through `script.Parent…`; there are no globals besides what `ctx` carries. All engine calls that can throw are wrapped in `pcall` and converted to protocol errors with a code from §2.2.

## Request flow

1. Bridge frame → bootstrap (`Link.receive` reassembles chunks) → `hub/link.luau` decodes → `hub/init.luau` `handleBridgeFrame`.
2. `routeTarget(frame)` picks the executing DM: `body.dm` for `playtest run_until/install/uninstall/hotpatch` (default `server`), `input` and `observe player` (default `client`); `push` and `persist_sync` always run on the hub (`push`'s `body.dm` names the play DM that receives `push_apply`); `req.dm` otherwise (`edit` default).
3. `edit` → `Dispatcher:handle` (one `task.spawn` per request, deadline timer, cancel). Other DMs → the original frame text is forwarded to the peer over the star with the **same id** and a per-request expiry timer (deadline + 5 s); the agent's `res` / `progress` frames are relayed back unchanged (the hub only fills `dm` if missing and records persisted controllers). Every response goes through `link.sendOrQueue`, so one produced while the WebSocket is between the bootstrap's reconnects is delivered after `relinked()`; a response that cannot be JSON-encoded is replaced by an `internal` error.
4. Handlers receive `(req, ctl)`. They return the response `body` table, or throw `util.perr(code, message, extra?)`. Any other thrown value becomes `internal` with a traceback.

`ctl` (`types.Control`): `checkCancel()` (throws `cancelled`), `cancelled()`, `progress(note, pct)` (rate-limited to 4/s), `onAbort(fn)` (runs before a timeout / hard cancel kills the handler thread — use it to roll back), `remaining()`.

### Writes and the queue

Ops registered with `isWrite = true` (`run`, `selftest` on the hub) are exclusive per DM. A write that arrives while another runs (or while others already wait) joins a FIFO queue instead of failing:

- the queue is 500 deep; the 501st answers `busy` at once;
- the request's `deadline_ms` is absolute from arrival — a queued request that expires before it starts answers `timeout` without ever running;
- a `cancel` for a queued request answers `cancelled` immediately (nothing to unwind); a running one keeps the cooperative-then-hard cancel;
- a request that has waited 250 ms gets exactly one `progress` frame `"queued behind N"` (N = requests ahead of it, the running one included);
- when the running write finishes, the next queued one starts (`Dispatcher.pump`, iterative so a burst of trivial writes never nests coroutines); `failAll` / `cancelAll` pause the pump so a bulk cancel never starts a write only to kill it;
- **draining (L3)**: launches within one frame share an 8 ms slice (the same budget `S.yield()` honours). The dispatcher counts Heartbeats; the first launch of a frame (queued or direct) starts the slice, every launch hands its start to the handler as `ctl.sliceStart` — `S.new` reads it, so a program's `S.yield()` measures the slice from the burst start rather than from its own launch — and once the launches of that frame have used it the pump continues from the next Heartbeat (`task.delay(0)`, never yielding the caller). Worst case per frame: 8 ms plus the time to the running program's next `S.yield()` (a program that never yields runs to completion). A write that itself runs for many frames simply starts a new slice when it finishes. `Dispatcher.stop()` releases the Heartbeat connection (hub and agent call it from `stop()`; the selftest's private dispatchers do too).

Reads never queue. `run` with `dry_run` still answers `busy` when no ChangeHistory recording can be opened (there would be nothing to roll back). The hub's `observe status` reports `writeQueue {active, waiting}`.

### The change flush (`runner.flushDeferred`)

`DescendantAdded` / `DescendantRemoving` are deferred signals, so a run's change counts are only complete after the handlers queued by the program have run. Measured live, waiting one Heartbeat for that made every `run` cost a frame (33 queued writes ≈ 530 ms). `runner.run` now flushes without a frame: it creates an unparented sentinel `Folder`, connects its `DescendantAdded`, parents a child (queuing one more deferred handler *after* the program's), then `task.defer`s a resume of the current thread and yields. Deferred signal handlers and `task.defer` share the same FIFO invocation point, so when the resume comes and the sentinel has fired, every handler queued before it has fired too. If the sentinel fired synchronously the behaviour is Immediate and nothing is waited; if it has not fired by the resume, one `task.wait()` follows as before. `run` with `response_format: "detailed"` reports which strategy ran as `flush: "immediate" | "deferred" | "frame"`, and the hub `selftest` check `run.flushSubFrame` fails when six change-making runs need more than two Heartbeats.

### Change journal filter (L4)

`Journal.record` drops anything whose service-level ancestor is `CoreGui`, `CorePackages`, `PluginGuiService`, `RobloxPluginGuiService`, `StudioService`, `RobloxReplicatedStorage`, `VoiceChatInternal`, `Stats`, or has a name / class starting with `RobloxReplicated` (`Journal.isIgnoredName`). This covers run change counts, `observe diff` and the throttled `change` events alike (live: a client `run` had reported `VoiceChatInternal` as its only change).

### Removals under Deferred signal behaviour

`DescendantRemoving` handlers run *after* the detachment when `SignalBehavior` is `Deferred` (the default), so the instance's `Parent` is already `nil` and the ancestry cannot be walked. The journal keeps `parents`, a weak-keyed map `instance → last known parent`, filled by every `record` that sees a live ancestry (each `DescendantAdded`, moves included) and by a snapshot of the ignored trees at `start` (`Journal.snapshotIgnored`, ≤ 20 000 instances, so a pre-existing CoreGui element removed later is still recognised as internal). `Journal.locate` follows the live chain first and the remembered parents after, returning the service-level ancestor and the path the instance *had* (`Workspace.Old.Child`); the L4 filter applies to that ancestor. A removal whose origin was never seen is counted under the instance's own name rather than dropped. The selftest covers it (`journal.removedAfterDetach`, `run.changesRemoved`: `S.destroy` inside a run reports `changes.removed ≥ 1` with the former path).

## Playtest state machine (`hub/playtest.luau`)

A test becomes known in one of three ways, and every state change emits a `playtest` event **and** an extra `hb` (`Playtest.onChange` → hub heartbeat):

| Path | How it is recognised | Mode |
|---|---|---|
| `playtest start` | the hub calls `ExecutePlayModeAsync` / `ExecuteRunModeAsync` / `ExecuteMultiplayerTestAsync(players, {})` and waits for the peers (20 s; 40 s for multiplayer, whose clients are separate Studio processes 2–4 s apart) | as requested |
| Studio's Play / Run button | `EditModeActive` flips false → `starting`; `running` once the server peer is up | inferred |
| A test started elsewhere (e.g. a multiplayer test from another tool) | a `server` peer says hello while nothing is starting or running — the edit DM never leaves edit mode in a multiplayer test, so `EditModeActive` is silent | inferred |

Inference waits up to 3 s for a client: none → `run`; a client with `userId > 0` → `play`; only test players (`userId ≤ 0`, `Player1`…) → `multiplayer` with `players` = client count. A client joining after the grace period revises a `run` verdict (a second `running` event with `detail: "mode revised…"`) or raises `players`. A test whose edit DM stayed in edit mode ends when its server peer disconnects (1 s grace); the others end on `EditModeActive`.

`stop` sends `endtest` to the server peer whenever one exists, whatever the bookkeeping says, then waits for `EditModeActive` (play/run) or for the server peer to disconnect (multiplayer/external). "no playtest was running" is answered only with no server peer **and** `EditModeActive == true`. `add_players {count}` → server agent `addplayers` → `StudioTestService:AddPlayers(count)`, then waits up to 40 s for the new client peers. `status` reports `mode`, `players`, `elapsed_s`, `externally_started`, `edit_mode_active`, `peers`, `controllers`, `persisted`.

Background waits carry a generation counter (`self.gen`, bumped on every start / detect / end) so a stale inference thread never overwrites a newer state.

## Persisted controllers (`hub/persist.luau`, bridge `persist_sync`)

The durable list lives in the **bridge** (per session in memory and in `<home>/persist/<placeId>.json`), because `plugin:GetSetting` returns `nil` on Studio 0.738. The hub keeps only an in-memory registry of `{dm, name, code}`:

- whenever the hub connects (every `hello`, including the one after a bundle push / runtime restart) the bridge sends `persist_sync {controllers: [{dm, name, code}]}` — as a `req` with `op = "persist_sync"` (answered `{persisted, rejected, installs_issued}`) or as a bare frame of the same kind (no answer). `Persist.replaceAll` **replaces** the registry (never merges); malformed entries are counted and warned about, `dm: "client"` is normalised to `client:1`, and of duplicate `dm + name` pairs the last wins;
- between syncs the hub mirrors what it relays for the bridge: an acknowledged `install persist=true` is `remember`ed (the install response gains `persist_source: "bridge"`), an acknowledged `uninstall` — or an install of the same name **without** `persist` — is `forget`ed (the latest install decides);
- `Playtest.onPeerConnected` still installs every entry for that DM on its hello, so a new playtest, a late-joining client and a hub runtime restart (agents restart with the pushed bundle first, then the queued install reaches the new agent runtime) all get them back.

`Playtest.synced[dm][name]` records which persisted controllers a connected peer already received (set on a hello install and on relayed install acks, cleared when the peer leaves). A `persist_sync` that arrives after a peer's hello therefore installs only what that peer is missing — it never unloads and reloads a controller that is already running. `Playtest.failed[dm][name] = {code, error}` records a persisted install the peer refused: the sync the bridge sends after every later install / uninstall skips it while its code is unchanged (one `controller state: "error"` event, not one per sync); a new hello of that peer, a changed code or an acknowledged relayed install / uninstall of the name clears it, and `playtest status → persisted[].error` shows it meanwhile. `playtest status → persisted` and `playtest list → persisted` list `{dm, name, bytes, persist: true, source: "bridge"}`; the hub's `observe status` carries their count as `persisted`. There is no size cap in the hub any more (the bridge owns the store) and nothing is cleared on `plugin.Unloading` (the list dies with the runtime; the bridge re-sends it on the next hello).

## Push a tree into a live playtest (`hub/push.luau`, agent `push_apply`)

`push {paths, dm?, parent?, replace?}` resolves each edit-DM path (≤ 200; services, overlapping instances and parentless instances without `parent` are `bad_request`), serialises them with `SerializationService:SerializeInstancesAsync` (measured: 200 parts ≈ 3.9 KB in 17 ms), base64-encodes with `EncodingService` (≤ 4 MB of text, else `bad_request`) and sends the agent op `push_apply {b64, parent?, parents[], names[], classes[], replace}` through the internal request path (`h-<n>` ids, chunked at 16 KB by the star). The agent decodes, `DeserializeInstancesAsync`, parents each root under `parent` or its original parent's path (matched by position, then by name), destroys everything on a missing parent (`bad_request`) and answers `{paths, count, bytes, apply_ms, replaced}`. With `replace` (default **true**) a child already under the target parent with the same `Name` **and** `ClassName` is detached (`Parent = nil`, so a failure later in the same push can put it back) before the new root is parented and destroyed once every root is in place; `replaced` counts them (live before this: two `PushProbe` models after two pushes). `Terrain`, `Workspace.CurrentCamera`, player characters (`Players:GetPlayerFromCharacter`; multiplayer clients are named `Player1..N`) and same-named siblings of another class are never detached and are reported as `skipped: [{path, reason}]`. `replace: false` keeps both. Pushing to `server` replicates to every client; pushing to a client is local to that client. `push` is a hub read: it never waits behind edit-DM writes.

## Startup output of play DMs (`Logs.seedHistory`)

Game scripts print before the agent runtime exists. A fresh agent (`ctx.lastSeq == 0`) reads `LogService:GetLogHistory()`, keeps the lines stamped since its DM started (`os.time() - time() - 1`, at most 200) and emits each as a `log` event with `history = true` and the line's own `wall`; the hub stamps real seqs, so `observe logs since=N` pages them like live output. A replacement runtime (`ctx.lastSeq > 0`, bundle swap mid-test) seeds locally with seq 0 instead — its predecessor captured those lines live. Because LogService mirrors server prints into the client's history in a Play test, the hub drops a history line whose level and text match a journaled line with a wall-clock stamp within 2 s (`Logs.hasSimilar`, last 400 entries). The hub's own seed keeps seq 0 (it would otherwise create gaps in the bridge's journal). `observe logs` accepts `dm: "all"` (same as omitting `dm`): every DM's lines, each carrying `src`; items seeded from history carry `history: true`.

## The edit DM and `S.destroy`

`Instance:Destroy()` locks `Parent`, so a ChangeHistory `Cancel` (an error, `dry_run`) or a later Undo cannot bring a destroyed instance back — the multi-agent build lost two GUIs to a `dry_run` this way. On the edit DM `S.destroy` therefore sets `Parent = nil` and keeps the instance in `S.detached` until `hub/run.luau` has finished the recording (Commit or Cancel); the run body reports `detached: n`. Play DMs still `Destroy()` (ephemeral). Program text containing `:Destroy(` makes the run body carry `warnings: ["program calls :Destroy( …"]`. The selftest creates a folder *outside* the recording, detaches it inside, cancels, and checks that it is back (`S.destroy.restoreOnCancel`).

## Other S additions

- `S.ensure(path, class?, props?) -> (Instance, created)` — resolves the dotted path; when absent creates the missing segments (Folders above the leaf, the leaf as `class`, default `Folder`) and applies `props` to the *new* leaf only; an existing instance of another class is an error only when `class` was given (without it, whatever exists is returned). Participates in the recording like `S.new`. Children of `game` are never created (services only).
- `S.set` / `S.new` / `S.ensure` collect engine-refused properties into `S.unwritable` (below); `runner.run` mirrors a non-empty list into `warnings` as well (`runner.unwritableWarning`), because the engine's message for a misspelt name is the same `not a valid member`.
- `S.set` / `S.new` collect properties the plugin VM refuses (`lacking capability`, `not a valid member`) into `S.unwritable` (`{path, prop, reason}`, ≤ 100) instead of throwing; `runner.run` copies a non-empty list into the run body as `unwritable`. Every other property error still throws.
- `S.script.get(path, {from, to}) -> (text, total_lines)` — line ranges (1-based, inclusive); without a range the whole source plus the line count. `observe {what: "script", path, from?, to?}` returns `{path, class, from, to, lines, total_lines, text, truncated?, next_from?}` sized to the response format budget (≈ 20 KB concise / 200 KB detailed) on whole lines, exempt from the §7 8 KB string cap; on the edit DM both read the live editor buffer.
- `S.pathTo(pos, timeout?, agentParams?) -> (reached, reason?)` (client DMs; `ctx.pathTo` in controllers) — `PathfindingService` path (`AgentCanJump`, radius 2, height 5 by default), walked waypoint by waypoint with `MoveTo` re-issued every Heartbeat and `Jump` on Jump waypoints; a waypoint without progress for 1.5 s gets one jump, then the path is recomputed from the current position (≤ 3 computes; a recompute whose path ends no closer than the previous one stops early). Reasons: `wrong_dm`, `no_character` (also mid-walk: died, despawned, root part gone), `no_path:<PathStatus>`, `compute_error: …`, `unreachable:<studs>` (every waypoint walked, goal still off the navmesh), `stuck`, `timeout`. The walk is stopped (`MoveTo(rootPart.Position)`) on every exit; both helpers block the calling thread. `S.moveTo` stays the straight-line walk and now also returns a reason (`no_character`, `timeout`).
- `observe {what: "script"}` on a single line longer than the budget: the text is cut, `line_cut: true`, `next_from` stays at that line and `note` names the alternatives (`detailed`, `S.script.get` + `string.sub`).
- `observe tree` with an explicit `root` always returns that root node (`n: 0` when empty); only a whole-DataModel tree omits empty services.

## Geometry rules (`shared/geometry.luau`)

"Parts in parts" is the mistake every agent-built scene shows: decks clipping walls, ramps buried in platforms, pillars sunk into tiles, and BaseParts parented under BaseParts in the Explorer. Telling the agent does not work; the runtime enforces it (protocol §4.1 `geometry`, §4.2 `observe geometry`, §6.2 helpers).

**What counts.** An *overlap* is a pair of BaseParts whose volumes penetrate each other by more than `tolerance` (0.05 studs): `workspace:GetPartBoundsInBox(part.CFrame, part.Size − 2·tolerance, Exclude{part})` lists the candidates for each part (the engine answers with bounding boxes, `RespectCanCollide = false`, at most 100 per part), then a pair of two *block* `Part`s is confirmed by a separating-axis test of the oriented boxes — exact, `depth` = the smallest axis overlap — while a pair involving any other shape (wedge, sphere, cylinder, mesh, union, truss) is kept as the engine reported it, with the overlap of the world AABBs as `depth` and `approximate: true`. Touching faces (a tile on a floor, wall segments end to end) are therefore never overlaps: the shrunk query box does not reach the neighbour. Terrain is never a candidate; a pair with a `CanCollide = false` part is reported and flagged `decor`; parts with `CanQuery = false` are invisible to the engine query; parts outside Workspace cannot be queried and are counted as `outside` (nesting still checked). Each unordered pair is reported once. A *nested* violation is a BasePart whose `Parent` is a BasePart — Attachments, Decals, Textures, Lights, constraints and scripts under a part are fine; Models and Folders are the containers.

**Caps and budgets.** `geometry.overlaps(parts, {tolerance, max, against = "all" | "self", maxParts, budget})` checks each part once (a list may name one twice) and at most `maxParts` of them (5000; a larger list is stride-sampled and the report says `sampled`) within a *work* budget (0.5 s after a run, 2 s for `observe`; running out also sets `sampled`), yielding one Heartbeat after every `SLICE_S` = 8 ms of work when the calling thread can yield (`coroutine.isyieldable()`), so a big audit never freezes Studio for its whole budget; `ms` is work time and `yields` the frames waited. It keeps at most `max` (200) entries per list while `totals` count everything; warning lines are cut to 1 KB (`WARNING_MAX_BYTES`). `geometry.report(parts, opts)` = overlaps + nesting (`include_nested = false` skips the latter; `partial = true` forces `sampled` when the caller's part list was already incomplete); `geometry.trim(report, 50)` is the run body's copy; `geometry.warnings(report)` is one line per non-empty list naming the first offender.

**Run integration.** `runner.run` takes `geometryPolicy` (`"warn" | "reject" | "off" | nil`). After the change flush, while the journal mark is still held, `journal:addedInstances(cursor, 5000)` returns the BaseParts the run added (ring entries keep the instance, so a part the program moved after creating it is still the right one; `sampled` when the run added more than 5000 or more than the 4000-entry ring holds), `runner.geometryCheck` adds the instances the program moved, resized or re-parented through S (`S.touched`, filled by `applyProps` for CFrame / Position / Size / Orientation / Rotation / PivotOffset / Parent, by `S.placeOn`, `S.snapToGrid`, `S.grid` and the `PlaceOn` prop; Models expand to their parts; `runner.run` empties the set when the program starts, so one S serving several programs reports per program) and builds the report — only for a program that succeeded (an error rolls back anyway) and also for `dry_run`. The work budget is `min(0.5 s, ctl.remaining() / 2)` (never below 50 ms), so the check cannot run a good program into its deadline. `warn` (the hub's default when `body.geometry_policy` is absent) puts `geometry` in the body when it is non-empty and appends the warning lines to `warnings`, after the `unwritable` line. `reject` fails the run with `error.code = "geometry_violation"` carrying `geometry`, `warnings`, `output`, `changes` — `hub/run.luau` cancels the recording like any error and adds `undo` (`cancelled` | `unavailable`); the agent adds `undo: "n/a"` and says the parts were not removed. `protocol.err` keeps those extras (the earlier builders dropped everything but `stack` / `output`). Play DMs check only when the body names a policy (the bridge sends none by default there). An unknown policy value is `bad_request` before any recording is opened. A failing check (an engine call throwing) is warned about and the run answers as if nothing was found.

**`observe geometry`** `{root?, max?, tolerance?, include_nested?}` collects every BasePart under `root` (default Workspace, Terrain never, ≤ 50 000 collected) and answers `{root, parts, overlaps, nested, checked, sampled, ms, totals, outside?, note?}` — `max` is the number of parts checked (5000), the lists hold ≤ 200 entries each and `observe.cap` halves `overlaps` / `nested` (with `truncated: true`) when the encoded result exceeds the format budget. It runs on the hub and on agents (a play DM audits its own copy of the scene).

**S helpers (§6.2).** `S.placeOn(inst, target, {align = "keep" | "center", gap = 0})` rests a BasePart / Model on a BasePart / Model (bottom of the world AABB on the top of the target's, rotation kept) and returns it; `PlaceOn = target` (or `{target, align, gap}`) in any props table (`S.part`, `S.new`, `S.set`, `S.ensure`) does the same after every other property, so `Size` and `CFrame` are applied first. `S.fits(cframe | Vector3, size, {ignore, tolerance, max})` → `(fits, blockingPaths)` — exact against block Parts, bounds-based against the rest; `S.fits(partOrModel, opts?)` tests the instance's own box and ignores the instance itself. `S.overlaps(target, opts)` (a BasePart / Model / Folder / path or a list of those) → the overlap list plus `{checked, total, sampled, ms, outside}`; `S.nested(target)` → the nested list; `S.snapToGrid(inst, step | Vector3)` rounds the pivot position.

**Selftest.** `geometry.overlaps` (a block resting on another is not an overlap; one sunk 0.5 studs reports `depth 0.5`, a sunk WedgePart is `approximate`; a part listed twice is checked and paired once), `geometry.touchingGrid` (400 floor tiles edge to edge plus 100 resting on them report nothing — `ms` / `yields` in the detail say what the slicing cost — and one tile pushed 0.25 studs sideways is the single pair afterwards), `run.geometryMoved` (a pre-existing part pushed into a slab through `S.set` is reported with `checked: 1`; `S.placeOn` in the next run clears it), `geometry.nested` (a part under a part, an Attachment ignored, a root Instance accepted), `S.placeOn` (keep / center / gap, the `PlaceOn` prop, a Model target, a Folder target refused), `S.fits` (clear, sunk, ignored, touching, self), `run.geometryWarn` (`geometry` totals, `checked`, the two warning lines), `run.geometryReject` (`geometry_violation` with the report; `off` and absent stay silent) and `observe.geometry` (an explicit root, `include_nested: false`, an unknown root refused). All parts sit at y ≈ 5000 under the selftest folder, inside the cancelled recording. What only Studio can prove: that `GetPartBoundsInBox` sees parts created in the same frame in edit mode (the run check follows the program inside one frame) — if the live selftest shows `geometry.overlaps` finding nothing, the check needs a Heartbeat before querying.

## Place identity

`observe status` → `place` and every `hb` carry `universeId` (`game.GameId`), `creatorType` (`"User"` | `"Group"`) and `creatorId` (`game.CreatorId`) besides `placeId` / `placeName`; the bootstrap hello cannot be extended, so the bridge reads them from the first `hb`.

## Adding an op

1. Add the op to `docs/protocol.md` §4 or its Notes (request body, response body, error codes) — the doc is the contract.
2. Implement the handler. Shared logic goes in `runtime/shared/…`; DM-specific logic in `hub/` or `agent/`.
3. Register it: `dispatcher:register("myop", function(req, ctl) … return body end, isWrite)` in `hub/init.luau` and/or `agent/init.luau`.
4. If the op targets play DMs, teach `routeTarget` in `hub/init.luau` where it runs (which `body` field carries the dm and the default). A hub op that talks to an agent internally (like `push`) uses `request(dm, op, body, timeoutS)` from `hub/init.luau` and registers the agent-side op in `agent/init.luau`.
5. Validate inputs with `util.num` / type checks and throw `util.perr("bad_request", …)`; cap outputs (`observe.cap`, `protocol.OUTPUT_*`, `protocol.capEvent`).
6. Track every signal connection / thread you create and release it in `stop()` (or via `ctl.onAbort` for per-request resources).
7. Run the parse/type check below and, in Studio, `selftest` plus the new op.

## Adding an event type

Call `env.emit({ type = "…", … })`. The hub stamps `v/kind/seq/t/wall/src` and caps the payload at 4 KB; agents stamp `aseq` and the hub assigns `seq` on relay. Add the type to §2.5. A playtest state change should go through `Playtest.emitState` so it also triggers an `hb`.

## Checking without Studio

```powershell
npm run luau:check
```

`scripts/luau-check.mjs` writes a Rojo-style sourcemap that mirrors the bootstrap's tree rules (one `Folder` per path segment, `init` as a plain `ModuleScript`), fetches `globalTypes.d.luau` once into `%TEMP%\studio-live\luau` (or uses `STUDIO_LIVE_LUAU_DEFS`), and runs `npx --yes luau-lsp analyze --no-strict-dm-types` over every `plugin/**/*.luau`. It exits non-zero on any error and on a UTF-8 BOM (a BOM is a syntax error for the Luau parser and would break the packed bootstrap). The only expected output is the advisory `DeprecatedApi` lint on `version()` in the bootstrap.

Without Studio, the bridge side of the contract is exercised by `npm run selftest` (real bridge + `scripts/fake-hub.mjs`); the Luau side needs a live Studio: after connect, send `{"kind":"req","op":"selftest"}` and run `observe status`, `run`, `playtest start` → `install` → `run_until`. The hub `selftest` includes `dispatcher.writeQueue` (a private dispatcher with two fake write ops plus a read, a queued timeout, a queued cancel and the "queued behind 1" progress frame — it takes ≈ 0.5 s), `dispatcher.drain` (40 queued writes that each yield once must finish within a few Heartbeats, sharing one `ctl.sliceStart` per frame), `persist.registry` / `persist.sync` (the in-memory registry and the replace semantics of `persist_sync`), `journal.ignoresInternal` (services, their descendants and detached descendants), `journal.removedAfterDetach` (a detached instance is counted with its former path), `logs.dmAll` / `logs.historyDedupe` (server-only matching), `query.treeExplicitRoot` (also with `classes`), `util.sliceLines`, and — inside the cancelled recording — `S.set.unwritable`, `run.unwritableWarning`, `S.ensure` (with and without a class), `S.pathTo.wrongDm`, `S.script.getRange`, `observe.script` / `observe.scriptBudget`, `run.escapes` (`"\n"` and `"[^\n]+"` inside Luau strings compile), `run.changesSameFrame`, `run.changesRemoved`, `run.flushSubFrame` (six change-making runs within two Heartbeats), the geometry checks (`geometry.overlaps`, `geometry.nested`, `S.placeOn`, `S.fits`, `run.geometryWarn`, `run.geometryReject`, `observe.geometry` — see "Geometry rules"), `S.destroy` and, after the Cancel, `S.destroy.restoreOnCancel`. The selftest leaves nothing behind: the pre-created `StudioLiveSelftestPre` folder is destroyed for real at the end.
