# Studio Live — wire protocol v1

Three links, one frame vocabulary. All frames are JSON objects with `"v": 1` and a `"kind"`. Text only (Studio's WebSocket `Send` is string-only). Unknown kinds/fields must be ignored, never fatal.

| Link | Transport | Who |
|---|---|---|
| L1 | WebSocket `ws://127.0.0.1:47800/studio` | bridge ⇄ **hub** (edit-DM runtime, via the bootstrap) |
| L2 | `PluginConnection:SendMessage` (string) | hub ⇄ **agent** (each play DM runtime, via the bootstrap) |
| L3 | WebSocket `ws://127.0.0.1:47800/events` + HTTP long-poll | bridge → Claude Code (Monitor) / any client |

Port: `47800` default, `STUDIO_LIVE_PORT` overrides. Bridge listens on `127.0.0.1` and `::1`. Studio connects using the literal `127.0.0.1`.

## 1. Bootstrap ⇄ bridge (before the runtime exists)

The bootstrap (the only code on disk, `plugin/bootstrap.luau`, packed as `StudioLive.rbxmx`) knows only: role detection, the L1/L2 hello, bundle loading, and reconnect. Everything else is in the bundle.

Role: `edit` when `not RunService:IsRunning()`; `server` when running and `IsServer()`; `client` otherwise.

### 1.1 Edit DM (L1)

1. Open WS; on `Opened` send `hello`:
```json
{"v":1,"kind":"hello","proto":1,"bootstrap":"1.0.0","role":"edit",
 "session":"<GUID generated at plugin load>",
 "studio":{"version":"0.738.0.7381393","placeId":1234567890,"placeName":"PIRATES","dataModelName":"Place1"},
 "lastSeq":0}
```
`lastSeq` = highest event seq the hub has emitted (0 on fresh load; the runtime updates it so a *re-delivered* bundle after reconnect can resume numbering).
2. Bridge replies:
```json
{"v":1,"kind":"hello_ack","proto":1,"bridge":"1.0.0","serverTime":1789000000000,"ackUpto":0,"bundle":{"hash":"sha256-…","entry":"runtime/init","modules":{"runtime/init":"…luau…","runtime/hub/link":"…"}}}
```
   The bundle may instead arrive as separate `bundle` frame(s) (see §3 chunking) when large; `hello_ack.bundle` may be `null` and followed by `bundle`.
3. Bootstrap builds an in-memory tree (unparented `Folder` root named `StudioLiveRuntime`; path `a/b/c` → `Folder a` → `Folder b` → `ModuleScript c`; a segment named `init` becomes a `ModuleScript` **named `init`** under its folder — plain, no Rojo folding), requires `entry`, and calls
   `runtime.start(ctx)` with
   `ctx = { plugin = plugin, role = "edit", session = session, link = Link, bundleHash = hash, bootstrapVersion = "1.0.0" }`.
   `Link` (owned by the bootstrap, survives runtime reloads): `Link.send(frameString)`, `Link.onFrame(fn) -> disconnectFn` (raw text frames from the bridge except `hello_ack`/`bundle`/`chunk`, which the bootstrap consumes), `Link.isOpen()`, `Link.stats()`.
4. Reconnect: exponential backoff 0.5 s → 5 s, jittered; proactive reconnect every 25 min (Studio may close streams at 30 min). On every (re)open the bootstrap sends `hello` again and gets a new `hello_ack`; if `bundle.hash` differs from the running one, it calls `runtime.stop()` (best effort, pcall) and starts the new bundle; if equal, it calls `runtime.relinked()` so the hub re-sends unacked events.
5. `plugin.Unloading` → `runtime.stop()`, close WS.

### 1.2 Play DMs (L2)

1. Wait for `PluginConnectionService:GetPluginConnectionsOfType(Edit)[1]` (poll 50 ms, up to 30 s; also listen to `.Connected`). Exactly one exists.
2. `BindToMessage` first, then send `hello` over the connection:
```json
{"v":1,"kind":"hello","proto":1,"bootstrap":"1.0.0","role":"server","targetId":"<PluginConnection.TargetId>","userId":100000001,"playerName":"roblox_user_100000001"}
```
   (`userId`/`playerName` only on clients, from `Players.LocalPlayer`.)
3. The hub replies with `hello_ack` (no bundle) **and** the bundle as `chunk` frames (§3), then `bundle_end`. The bootstrap assembles, builds the tree, and calls `runtime.start(ctx)` with `role = "server"|"client"`, `link = Link` (same API, backed by the PluginConnection), `hubTargetId`.
4. If the hub is not running (no bridge), the agent bootstrap keeps waiting silently; when a hub appears later it receives `hello` again because the hub sends `{"kind":"probe"}` to every Test connection on its own start and the bootstrap answers with `hello`.
5. The connection cannot reconnect (one-shot per playtest); on `Connected=false` the runtime is stopped.

## 2. Requests, responses, events (all links)

### 2.1 Request (bridge→hub, hub→agent)
```json
{"v":1,"kind":"req","id":"r-17","op":"run","dm":"client:1","deadline_ms":30000,"body":{…}}
```
- `id` unique per bridge process (`r-<n>`); the hub forwards to an agent with the **same id**; agent responses are relayed unchanged.
- `dm`: `"edit"` (default) | `"server"` | `"client"` (= lowest-numbered connected client) | `"client:N"` (N = 1-based join order in this playtest).
- `deadline_ms`: the executor must fail with `error.code="timeout"` after this; default 30000.
- The hub answers immediately with `error.code="no_peer"` if `dm` is not connected.

### 2.2 Response
```json
{"v":1,"kind":"res","id":"r-17","ok":true,"dm":"client:1","body":{…}}
{"v":1,"kind":"res","id":"r-17","ok":false,"dm":"edit","error":{"code":"luau_error","message":"…","stack":"…","output":[…]}}
```
Error codes: `luau_error` (runtime), `syntax_error`, `timeout`, `no_peer`, `bad_request`, `cancelled`, `disconnected`, `busy`, `unsupported`, `internal`, `geometry_violation` (a `run` with `geometry_policy: "reject"` whose parts overlap or nest, §4.1; the error carries the `geometry` report).

### 2.3 Progress (optional, any executor → bridge)
`{"v":1,"kind":"progress","id":"r-17","note":"placed 812/2000","pct":0.41}` — at most 4/s per request.

### 2.4 Cancel (bridge → hub → agent)
`{"v":1,"kind":"cancel","id":"r-17"}` — executor stops cooperative work at the next `S.yield()`/slice boundary and answers `error.code="cancelled"`.

### 2.5 Event (hub → bridge; agent → hub which assigns `seq`)
```json
{"v":1,"kind":"ev","seq":10433,"t":1789.21,"wall":1789000123,"src":"client:1","type":"assert","name":"door_opens","ok":false,"detail":"expected Open, got Closed","path":"Workspace.Door","controller":"walker"}
```
- `seq` is assigned **by the hub**, monotonic per session, starting at `lastSeq+1`. `t` = `os.clock()` in the originating DM, `wall` = `os.time()`.
- Agents send `ev` without `seq`; the hub stamps it and forwards. Agents may include `"aseq"` (their local counter) for debugging.
- Event types (v1): `log` (`level`: print|info|warn|error, `msg`, `script?`), `error` (`msg`, `stack`, `script`), `assert` (`name`, `ok`, `detail?`, `controller?`), `milestone` (`name`, `data?`), `custom` (`name`, `data?`), `playtest` (`state`: starting|running|stopping|stopped|failed, `mode`, `detail?`), `peer` (`dm`, `connected`, `userId?`, `playerName?`), `selection` (`paths`), `job` (`id`, `status`, `note?`), `controller` (`name`, `state`: installed|unloaded|error, `detail?`), `change` (`added`, `removed` counts — emitted at most 2/s while the DM changes outside a run).
- Payload discipline: every `ev` ≤ 4 KB (truncate `msg`/`stack`/`detail` with `…[+N chars]`).

### 2.6 Ack (bridge → hub)
`{"v":1,"kind":"ack","upto":10433}` at least every 2 s while events flow. The hub retains unacked events (ring of 2000; oldest dropped with a `dropped` counter reported in the next `hb`) and re-sends them after `relinked()`. The bridge dedups by `seq`.

### 2.7 Heartbeat (hub → bridge, every 10 s and on peer changes)
```json
{"v":1,"kind":"hb","seq":10440,"t":1804.0,"peers":[{"dm":"server","connected":true},{"dm":"client:1","connected":true,"userId":100000001,"playerName":"roblox_user_100000001"}],"playtest":{"running":true,"mode":"play"},"dropped":0,"fps":60.1}
```
The bridge marks the hub stale after 25 s of silence.

## 3. Chunking (any link, any frame)
Frames larger than **16 KB** on L2, or **512 KB** on L1, are split:
```json
{"v":1,"kind":"chunk","cid":"c-9","i":0,"n":12,"data":"<slice>"}
```
Receivers concatenate `data` in order, parse the result as a frame, and process it. `bundle` on L2 is always chunked; the final assembled frame is `{"kind":"bundle","hash","entry","modules"}` followed by nothing else (no `bundle_end` needed — `i == n-1` completes it). The L2 payload cap is undocumented; 16 KB is conservative and measured-safe for strings ≤ 1 MB is *not yet* verified — keep chunks small.

## 4. Operations (`req.op` / `body`)

### 4.1 `run`
```json
{"code":"…luau…","args":{…},"undo_label":"agent: build arena","dry_run":false,"geometry_policy":"warn","timeout_ms":30000}
```
- Edit DM: `rec = ChangeHistoryService:TryBeginRecording("StudioLive", undo_label)`; on success `FinishRecording(rec, Commit)`; on error/cancel/timeout `FinishRecording(rec, Cancel)` (= rollback). If `rec == nil` (a playtest is running, or another recording is open) the program still runs and the response has `"undo": "unavailable"`.
- `dry_run`: run, then always `Cancel` (edit only); play DMs ignore.
- `geometry_policy` (`warn` | `reject` | `off`): after the program returned and the change flush ran, the BaseParts this run **added** (the journal's) plus the ones it **moved, resized or re-parented through `S`** (`S.set` / `S.batchSet` / `S.placeOn` / `S.snapToGrid` / `S.grid` and the `PlaceOn` prop — `S.touched`; a Model expands to its parts; a direct `part.CFrame = …` write is not tracked, `observe geometry` catches it later) — ≤ 5000 in all; a larger set is sampled and the report says `sampled` — are checked with `shared/geometry.luau` — `overlaps`: each part's box shrunk by `tolerance` (0.05 studs) is queried with `workspace:GetPartBoundsInBox`, so touching faces are never overlaps; a pair of block `Part`s is confirmed by a separating-axis test with the penetration depth in studs, every other pair (wedges, spheres, meshes, unions) is bounds-based and flagged `approximate: true`; `CanCollide = false` pairs are flagged `decor: true`; Terrain is never a candidate; each unordered pair once — and `nested`: BaseParts whose `Parent` is a BasePart (attachments, decals, lights, constraints and scripts under a part are fine; Models and Folders are the containers). `warn` (default): the response gains `geometry` (only when something was found; ≤ 50 entries per list plus `totals`) and one `warnings` line per non-empty list, e.g. `"3 overlapping part pairs (e.g. Workspace.Map.Deck ⟂ Workspace.Map.WallEast, 1.5 studs) — fix before continuing (move, resize or S.placeOn them); see geometry"`. `reject`: `FinishRecording(rec, Cancel)` — the program's effects are rolled back — and `error.code = "geometry_violation"` with the same `geometry` report, `warnings`, `undo: "cancelled"` and the captured `output`; when no recording could be opened (`undo: "unavailable"`) nothing is rolled back and the message says the parts were NOT removed. `off`: no check. The check yields a Heartbeat after every 8 ms of work and stops early (`sampled: true`) after 0.5 s of work or half of the request's remaining deadline, whichever is less; `geometry.ms` is that work time. Absent on a play DM: no check (ephemeral parts); the bridge always sends a policy on edit-DM runs (its default from `STUDIO_LIVE_GEOMETRY_POLICY`, `warn`).
- Environment: the chunk is compiled with `loadstring` (edit/server) or wrapped as `return function(S, ARGS, print, warn) <code> end` in a fresh `ModuleScript` (client, or when `loadstring` is unavailable). Globals available: `S` (resident API, §6), `ARGS` (= `args`), `print`/`warn` (captured **and** forwarded to Studio output), plus the normal Roblox globals (`game`, `workspace`, `task`, `Instance`, …). Top-level `return value` is captured.
- Response body:
```json
{"value":<json-safe>,"output":[{"level":"print","msg":"…","t":1789.2}],"duration_ms":12.4,
 "changes":{"added":2000,"removed":0,"paths":["Workspace.Arena"]},"undo":"committed|cancelled|unavailable|n/a","ephemeral":false,
 "geometry":{"overlaps":[{"a":"Workspace.Map.Deck","b":"Workspace.Map.WallEast","depth":1.5,"aClass":"Part","bClass":"Part"}],
             "nested":[{"path":"Workspace.Map.Pillar.Cap","parent":"Workspace.Map.Pillar","class":"Part"}],
             "checked":2000,"ms":3.2,"totals":{"overlaps":1,"nested":1}},
 "warnings":["1 overlapping part pair (e.g. Workspace.Map.Deck ⟂ Workspace.Map.WallEast, 1.5 studs) — fix before continuing (move, resize or S.placeOn them); see geometry", "…"]}
```
- Value serialization (§7). Output capped at 200 entries / 32 KB total (then `…[+N more]`). `geometry` / `warnings` are omitted when empty; `geometry.sampled: true` appears only when the check could not cover every part (`checked` says how many it did).
- Errors carry `stack` from `debug.traceback` and the captured `output` so far.

### 4.4 `input` (client DMs only)
```json
{"dm":"client:1","actions":[{"type":"key","key":"W","hold_ms":600},{"type":"key","key":"Space","down":true},{"type":"wait","ms":100},{"type":"key","key":"Space","down":false},{"type":"click","x":400,"y":350,"button":"left"},{"type":"move","x":600,"y":450},{"type":"look","dx":200,"dy":0},{"type":"text","text":"hello"},{"type":"focus","path":"PlayerGui.Hud.Input"}]}
```
- Implemented with `UserInputService:CreateVirtualInput()` cached per DM. `key` with `hold_ms` = down, wait, up; with `down` = single edge. `click` = down, 50 ms, up. Coordinates are **viewport pixels as seen in screenshots**; the agent adds `GuiService:GetGuiInset()` internally when hit-testing GUI (`gui: true`, default true). `look` requires `MouseBehavior=LockCenter`; the agent sets it for the action and restores it. `focus` calls `TextBox:CaptureFocus()`.
- Response: `{steps:[{i, ok, error?}], elapsed_ms}`. A step error does not abort the sequence unless `abort_on_error=true`.

## 5. L3 — fan-out to the agent

### 5.1 WebSocket `/events` (for Claude Code `Monitor({ws:{url:"ws://127.0.0.1:47800/events"}})`)
- One JSON object per text frame, ≤ 4 KB, batched ≤ 10 frames/s. When several events fall in one 100 ms window they are sent as **one** frame: `{"batch":[…events…],"seq":<last>,"dropped":0}`.
- Default kinds forwarded: `error`, `assert`, `milestone`, `custom`, `playtest`, `peer`, `controller`, `job`, `log` with level `warn`/`error`. `print`/`info` logs and `change`/`selection` are **not** pushed (poll them with `events`/`observe`). Query `?kinds=log,assert&levels=print` to change the filter per socket.
- Heartbeat frame every 30 s: `{"kind":"hb","seq":N,"alive":["edit","server","client:1"],"playtest":true,"dropped":0}`.
- `dropped` = events the journal had to discard since the last frame on this socket (ring overflow or rate limiting). A consumer that sees `dropped>0` or a `seq` gap calls the `events` tool with `since`.

### 5.2 HTTP `GET /events?since=N&kinds=a,b&timeout=25000` → `{"cursor":M,"events":[…],"dropped":k}`; long-polls up to `timeout` ms. `GET /status` → bridge + sessions + journal stats. `POST /rpc {"tool","args"}` → proxied tool call for secondary MCP processes.

## 6. The resident `S` API (Luau, available to `run`, `run_until`, controllers, skills)

Same module on every DM; functions that need a DM the code isn't on return `nil, "wrong_dm"`.

### 6.1 Query
`S.get(path) -> Instance?` (dotted path from `game`; `Workspace.Arena.Door` or full name), `S.path(inst) -> string`, `S.find{root?, name?, class?, tag?, attr?, max?} -> {Instance}`, `S.tree(inst, depth) -> table` (same shape as `observe tree`), `S.props(inst, names?) -> table`, `S.raycast(origin, dir, params?)`, `S.overlap(cframe, size)`, `S.distance(a, b)`.

### 6.2 Build/edit (edit DM; also usable in play DMs but ephemeral)
`S.new(class, props?, parent?) -> Instance` (props table incl. `Attributes = {…}` and `Tags = {…}`), `S.set(inst|path, props)`, `S.batchSet({{inst, props}, …})`, `S.clone(inst, props?, parent?)`, `S.destroy(inst|path|{…})`, `S.part(props) -> Part` (anchored, smooth plastic defaults), `S.model(name, children, parent)`, `S.grid{origin, cols, rows, step, make(i,j)}`, `S.box{cframe, size, …}`, `S.ui.screen(name, props)`, `S.ui.frame/text/button(parent, props)`.
All builders participate in the current ChangeHistory recording automatically.

Placement (the geometry rules of §4.1, `shared/geometry.luau`): `S.placeOn(part, target, opts?{align = "keep"|"center", gap = 0}) -> part` sets the part's (or Model's) Y so the bottom of its bounding box rests on the top of `target`'s (a BasePart or a Model's bounding box) `gap` studs above, keeping X/Z (`align = "keep"`, default) or centring on the target (`"center"`), rotation kept; `S.fits(cframe, size, opts?{ignore = {…}, tolerance}) -> (ok, blockers)` answers whether a box at that pose penetrates nothing deeper than `tolerance` (instances in `ignore`, with their descendants, excluded) and lists the blocking paths as the second value; `S.overlaps(instOrList, opts?) -> {overlap}` runs the §4.1 overlap check for the given BaseParts (or the BaseParts under the given containers / paths) and returns the same `{a, b, depth, aClass, bClass, approximate?, decor?}` entries; `S.snapToGrid(part, step) -> part` rounds the pivot position to multiples of `step` (number or Vector3). `S.part` / `S.new` accept `PlaceOn = target` in `props` as sugar for `S.placeOn(inst, target)` applied after the other props.

### 6.3 Scripts
`S.script.get(path) -> source`, `S.script.set(path, source)` (edit DM: `ScriptEditorService:UpdateSourceAsync`, preserves open-editor state; play DMs: direct `Source` write), `S.script.patch(path, find, replace, count?)`, `S.script.restart(path)` (toggle `Disabled`), `S.script.create(class, name, parent, source)`.

### 6.4 Play / controllers (`ctx` given to `load`)
`ctx.S`, `ctx.role`, `ctx.dm`, `ctx.name`, `ctx.assert(name, cond, detail?) -> cond` (emits `assert`), `ctx.milestone(name, data?)`, `ctx.emit(name, data?)` (→ `custom`), `ctx.log(msg)`, `ctx.onHeartbeat(fn(dt))`, `ctx.onEvent(signal, fn)` (auto-disconnected on unload), `ctx.every(seconds, fn)`, `ctx.after(seconds, fn)`, `ctx.player` (client: LocalPlayer), `ctx.character(timeout?)` (client: returns the Character **Model** once it has a HumanoidRootPart; nil on timeout), `ctx.input` (client: `key(k, hold)`, `press(k)`, `release(k)`, `click(x,y,button?)`, `move(x,y)`, `look(dx,dy)`, `text(s)`), `ctx.moveTo(pos, timeout?)` (client: `Humanoid:MoveTo` re-issued each Heartbeat until reached/timeout; returns reached), `ctx.state()` (player snapshot as in `observe player`), `ctx.storage` (table that survives reinstall of the same name).

### 6.5 Everywhere
`S.emit(name, data?)` (→ `custom` event), `S.log(msg)`, `S.yield()` (cooperative slice boundary: yields one Heartbeat if the running slice exceeded 8 ms; also the cancellation point), `S.wait(seconds)`, `S.json(value) -> string`, `S.role`, `S.dm`, `S.clock()`.

## 7. Value serialization (Luau → JSON)
`Instance` → `{"$i":"Workspace.Arena.Door","class":"Part"}`; `Vector3` → `[x,y,z]`; `Vector2` → `[x,y]`; `CFrame` → `{"p":[x,y,z],"look":[x,y,z]}` (plus `"c":[12 components]` in `detailed`); `Color3` → `"#rrggbb"`; `EnumItem` → `"Enum.Material.Plastic"`; `BrickColor` → name; `UDim2` → `[sx,ox,sy,oy]`; `buffer` → `{"$buf":len}`; functions/threads → `"<function>"`; tables: arrays vs maps by `#t`, depth ≤ 6, ≤ 500 keys, cycles → `"<cycle>"`. Strings > 8 KB are truncated with `…[+N]`.

## 8. Versioning
`proto` is 1. The bridge rejects `hello` with a different `proto` with `{"kind":"error","code":"proto_mismatch","message":…}` and closes. `bootstrap` semver is advisory; the bridge logs a warning to its `status` when the bootstrap is older than the one it ships.

## Notes

Decisions the bridge (`bridge/src`) made where the sections above leave room; the hub should match them.

- **`cancel_all` framing (§4.6):** a standalone frame `{"v":1,"kind":"cancel_all"}` like `cancel` (§2.4) — not a `req`; no response is expected.
- **`hello_ack.bundle` (§1.1):** inlined when the encoded `hello_ack` is ≤ 512 KB; otherwise `bundle` is `null` and a `{"v":1,"kind":"bundle",…}` frame follows immediately (chunked per §3). With `STUDIO_LIVE_DEV=1` the bridge pushes a fresh `bundle` frame to every connected hub whenever the runtime hash changes.
- **L1 chunking (§3):** the bridge slices frames > 512 KB into `chunk` frames whose `data` is ≤ 128 K characters (never splitting a surrogate pair). Inbound chunks are reassembled per `cid` once all `n` parts are present (any order); partial assemblies are discarded after 60 s.
- **Ack cadence (§2.6):** one `ack` at most 1 s after the first unacked `ev` (coalescing), and immediately on every `hb`. `hello_ack.ackUpto` is the highest seq in the bridge's journal for that session (0 when the bridge has never seen it), so a hub reconnecting to a restarted bridge re-sends everything it retains.
- **Dedup (§2.6):** the journal drops any `ev` with `seq ≤` the highest seq already stored for the session. Seq gaps are counted (`journal.gaps` in `/status`) but never filled retroactively.
- **`dm` routing (§2.1):** every tool sends `req.dm = <tool dm argument> ?? "edit"` and repeats `dm` inside `body` where the op documents it (`observe`, `playtest`, `input`). The hub routes by `req.dm`, so `playtest start|stop|status|list` reach the hub while `run_until|install|uninstall|hotpatch` with a `dm` reach that agent with the same `id`.
- **Deadlines (§2.1):** `req.deadline_ms` = the op's `timeout_ms` (default 30000). For `run_until` it is `timeout_ms + 5000` so a predicate timeout still arrives as a normal `{"result":"timeout"}` response. The bridge gives up on its own (local `error.code="timeout"` plus a `cancel` frame) 5 s after `deadline_ms`.
- **Job handles:** the request `id` (`r-<n>`) doubles as the `job_id` returned to the agent; `progress` notes are kept on the job (last 50).
- **Bridge-level error codes** (tool results only, never on the wire): `no_session` (no hub connected), `not_found` (job/skill), `port_in_use`, `proxy_unreachable`, and the capture codes `no_window | minimized | capture_failed`.
- **L3 framing (§5.1):** `/events` sockets always receive the `{"batch":[…],"seq","dropped"}` envelope, even for a single event. `dropped` on a socket counts only that socket's queue overflow (queue of 1000, one frame per 100 ms window). An event larger than the 4 KB frame budget is truncated field by field (`"truncated":true`). `/events` (WS and long-poll) serve the *active* session's journal unless `?session=<guid>` pins one.
- **Long-poll cursor (§5.2):** `cursor` is the seq of the last returned event; with no matching events it advances to the journal's latest seq so filtered-out events are not rescanned. `dropped` counts seqs after `since` that the ring had already evicted.
- **`POST /rpc` hardening (§5.2):** requests carrying an `Origin` header are refused (403) and `content-type: application/json` is required (415), so a web page cannot drive Studio through the loopback bridge.
- **Stale hubs (§2.7):** `stale` is informational (`/status`); requests are still sent and fail by deadline.
- **Active session:** the most recent `hello`/`hb` among *connected* hubs. Tools accept `session` (full GUID or a unique prefix).
